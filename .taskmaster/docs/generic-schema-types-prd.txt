# Keystone-Classic Generic TypeScript Schema Methods PRD

## Project Overview
This project adds generic TypeScript support to keystone-classic's type definitions to enable proper typing for mongoose schema methods. The goal is to eliminate TypeScript linting errors when accessing specific document properties in schema methods while maintaining 100% backwards compatibility.

## Problem Statement
The current keystone-classic type definitions lack support for:
1. Generic `KeystoneList<T>` interface where `T` is the specific document type
2. Proper typing for `schema.methods` that preserves the document-specific `this` context
3. Type-safe constructor that works with the existing `new keystone.List()` pattern

This results in TypeScript errors when accessing document properties in schema methods:
```typescript
// Current issue - TypeScript doesn't know about specific document properties
schema.methods.myMethod = function () {
  this.email; // ❌ Error: Property 'email' does not exist on type 'Document'
};
```

## Technical Requirements

### Core Implementation Strategy
**CRITICAL**: Use Constructor with Type Assertion pattern (Option A) as it:
- ✅ Requires no runtime JavaScript changes
- ✅ Works with existing codebase patterns
- ✅ Provides full generic typing support

- ✅ Can be implemented immediately

### Target File

**Position:** Add new interfaces at the end of the file, after existing type definitions

### Required Type Definitions

#### 1. Generic KeystoneList Interface
```typescript
/**
 * Represents a KeystoneJS List instance with generic document support.
 * @template T - The document type for this list (extends mongoose.Document)
 * @see /lib/list.js - Base list implementation
 */
export interface KeystoneList<T extends mongoose.Document = mongoose.Document> {
  /** The name of the list */
  key: string;

  /** The mongoose schema associated with this list */
  schema: mongoose.Schema<T> & {
    /** Schema methods with proper typing for 'this' context */
    methods: {
      [K: string]: (this: T, ...args: any[]) => any;
    };
  };

  /** The mongoose model */
  model: mongoose.Model<T>;

  /** List configuration options */
  options: KeystoneListOptions;

  /** Add fields to the schema */
  add(fields: KeystoneGroupFields): void;
  add(heading: KeystoneGroupHeading, fields: KeystoneGroupFields): void;

  /** Register the list with keystone */
  register(): void;

  /** Default sort configuration */
  defaultSort?: string;

  /** Default columns configuration */
  defaultColumns?: string;

  /** Create relationships */
  relationship(config: any): void;

  /** Get a configuration option */
  get(option: string): any;

  /** Set a configuration option */
  set(option: string, value: any): KeystoneList<T>;

  /** The field mappings for this list */
  mappings: KeystoneListMappings;

  /** All fields in this list */
  fields: { [fieldName: string]: KeystoneField };

  /** Underscore methods attached to the schema */
  underscoreMethods: { [methodName: string]: Function };
}
```

#### 2. Enhanced Keystone Interface with Constructor Support
```typescript
/**
 * Main KeystoneJS class with enhanced constructor support.
 * @see /lib/keystone.js - Main keystone implementation
 */
export interface Keystone {
  /**
   * List constructor that supports generic typing via type assertion
   * @param name - The name of the list
   * @param options - Configuration options for the list
   * @returns A new List instance
   */
  List: {
    new (name: string, options?: KeystoneListOptions): KeystoneList<any>;
    new <T extends mongoose.Document>(name: string, options?: KeystoneListOptions): KeystoneList<T>;
  };

  /** Get a list by name */
  list(name: string): KeystoneList<any>;

  /** Initialize keystone */
  init(config: any): void;

  /** Start keystone */
  start(callback?: (err?: Error) => void): void;

  /** Field types */
  Field: {
    Types: {
      Text: KeystoneTypeConstructorForTextType;
      Textarea: KeystoneTypeConstructorForTextareaType;
      Email: KeystoneTypeConstructor;
      Password: KeystoneTypeConstructor;
      Name: KeystoneTypeConstructor;
      Number: KeystoneTypeConstructorForNumberType;
      Boolean: KeystoneTypeConstructorForBooleanType;
      Date: KeystoneTypeConstructorForDateType;
      Datetime: KeystoneTypeConstructorForDateTimeType;
      Select: KeystoneTypeConstructor;
      Relationship: KeystoneTypeConstructorForRelationshipType;
      Location: KeystoneTypeConstructorForLocationType;
      CloudinaryImage: KeystoneTypeConstructorForCloudinaryImageType;
      CloudinaryImages: KeystoneTypeConstructorForCloudinaryImagesType;
      File: KeystoneTypeConstructorForFileType;
      Url: KeystoneTypeConstructor;
      Html: KeystoneTypeConstructor;
      Markdown: KeystoneTypeConstructor;
      Money: KeystoneTypeConstructor;
      Color: KeystoneTypeConstructor;
      Code: KeystoneTypeConstructorForCodeType;
    };
  };
}
```

## Usage Examples

### Current Problem (Before)
```typescript
import * as keystone from "keystone";

const MyList = new keystone.List("MyModel", {});

MyList.schema.methods.myMethod = function () {
  this.email; // ❌ TypeScript Error: Property 'email' does not exist
};
```

### Solution (After - Type Assertion Pattern)
```typescript
import { keystone, KeystoneTypes } from "@app-dir-source-root/keystone-server";
import { MyDocumentInterface } from "./types";

// Type assertion (RECOMMENDED)
const MyList = new keystone.List("MyModel", {}) as KeystoneTypes.KeystoneList<MyDocumentInterface>;

MyList.schema.methods.myMethod = function (this: MyDocumentInterface) {
  this.email; // ✅ TypeScript knows about email property
};
```
